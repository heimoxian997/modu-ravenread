# 墨读 · RavenRead

一个在本机管理和阅读 TXT 小说的工具，也是一位能查原文、记笔记、整理人物关系与剧情线的伴读助手。

导入小说后，可以直接阅读，也可以按章生成摘要、人物与世界观索引，让伴读围绕当前阅读进度回答问题。伴读记录保存在书籍中，不同聊天窗口可以继续使用已有的整理成果。

## 阅读与书库

- **TXT 导入**：识别文本编码和章节规则，预览解析结果，调整章节边界后确认入库。
- **正文与番外分离**：在导入时区分正文、番外等内容，番外不参与伴读检索与抽取。
- **本地书库**：管理书籍信息、目录和处理状态，从上次的位置继续阅读。
- **章节阅读器**：按章阅读、调整字号、跳转目录，自动记录阅读位置；支持查看当前位置附近的正文，以及人名和称呼的候选解释。

## 摘要、人物与世界观

长篇小说的信息按章节保存，既能查看整理结果，也能追溯它来自哪里。

| 功能           | 用途                                                                                 |
| -------------- | ------------------------------------------------------------------------------------ |
| 章节摘要       | 按章调用模型，整理摘要、关键事件、出场人物等内容；支持批量处理、暂停、续跑和单章重抽 |
| 人物卡         | 聚合截至指定章节的身份、性格、关系、已知事实等信息，展示字段来源章节                 |
| 人物变化时间线 | 查看某个人物在各章发生了什么变化，按章节范围或关键词定位                             |
| 别名与称呼     | 根据已经出现的称谓观测查找候选人物，辅助处理同名、化名和称呼歧义                     |
| 世界观条目     | 整理地点、组织、物品、功法与世界规则，支持查询和来源追溯                             |
| 编辑与重建     | 编辑整理结果，重建实体层和对应检索索引                                               |

正文采用父子切块：先召回较小的片段，再展开所属的较大上下文，减少只看到孤立句子的情况。本地检索使用 BGE-M3，相关检索支持稠密向量、稀疏检索融合与可选重排；页面提供检索和重排效果对比。

## 伴读 agent

可以直接使用阅读器里的伴读，也可以把 RavenRead MCP 接到 WorkBuddy 等支持 MCP 的客户端，使用自己的模型进行伴读。

伴读可以帮助你：

- 回顾某段前情，定位一个场景或一句原文。
- 查询人物在当前阶段的身份、关系和变化。
- 对照多个章节，梳理事件先后、动机与认知变化。
- 整理可复用的章节事件、人物关系和剧情线，留给后续聊天继续使用。
- 发现笔记或基础索引中的错误，修订笔记或提交纠错报告。

### 跟随阅读进度

伴读以阅读器当前章为边界，可以读取当前章及之前的正文；当前章按整章可读处理。正文、摘要、人物、称呼、笔记和剧情线均按对应时点过滤，后期写入的笔记版本不会提前出现在较早的阅读进度中。

对模型暴露的章号统一从 **1** 开始，第 12 章就填写 `12`。长章节和批量读取通过工具返回的 `cursor` 续读，无需模型计算字符偏移。

### 能跨窗口复用的笔记

笔记分为两层：

- **章节事件**：一条记录一个主要事件或状态，保存发生章、结论可知章、参与者和正文引文；区分原文明示与解释性判断。
- **剧情线与人物关系图**：把事件串成有名称的节点和连接，支持分支、汇合，以及先后、因果、线索、揭示和反驳关系。

查笔记时，服务端混合人物关联、关键词和本地语义向量，不要求问题与笔记使用相同措辞。默认只返回少量相关事件和局部图，也可以先浏览剧情线名称，再展开某个节点及相邻分支。

笔记向量首次在后台补建，之后按变化文本增量更新；相同文本复用缓存，只改连线不会重算节点向量。模型缺失、繁忙或索引尚未就绪时，仍可使用人物与关键词检索。

笔记修订保留版本历史，多窗口更新时检查版本冲突。关联事件被修正后，依赖旧版本的剧情节点会标记待核实，旧结论暂不作为有效依据。

在书籍详情点击“剧情线”，可以搜索已有整理，在剧情图与章节列表之间切换。点击节点查看完整结论、相邻分支、引用笔记和原文引文；待核实节点会单独标记，过期结论与连接隐藏。

回退阅读进度时优先展示当时可见的历史版本。只有后期整理版本的剧情线，会用中性标题展示已读章节的原文节点，隐藏后期结论、分支命名和因果解释；尚未读到的节点和线索不显示。

### 伴读 Skill

项目提供配套 Skill，指导外部 agent 按以下流程工作：

> 确认阅读进度 → 查已有笔记 → 按需求证原文 → 保存值得复用的新发现 → 回答。

已有记录足够、只是简单复述或证据不足时，可以跳过写入；有新发现时优先补充已有记录，避免重复积累。是否实际遵循流程，取决于客户端是否加载 Skill 及所用模型的执行情况。

WorkBuddy 可导入 [伴读 Skill 压缩包](artifacts/ravenread-companion-workbuddy.zip)。首次使用时明确要求“使用墨读伴读 Skill，通过 RavenRead MCP 回答当前书的问题”。源码位于 [skills/ravenread-companion](skills/ravenread-companion/)。

### 纠错审核

- **笔记与剧情线**：agent 可以依据正文直接修订，保存原因和版本，继续核对受影响的节点。
- **摘要、人物、别名与世界观**：agent 提交带来源和正文证据的纠错报告，由用户在书籍详情的“纠错审核”中查看修改前后、编辑建议并确认应用。

基础数据修改经确认后，重建对应实体层和索引；失败可以重试。重建期间，受影响的伴读检索会暂缓使用旧的派生结果。纠错不会修改小说原文。

## 使用流程

1. 导入 TXT，检查章节解析及正文、番外划分。
2. 打开阅读器，确认阅读位置；此时即可阅读和使用基础正文读取能力。
3. 按需生成正文切块、正文索引和章节摘要，再建立人物、世界观及摘要检索索引。
4. 在阅读器中使用伴读，或连接 MCP 并启用伴读 Skill。
5. 随阅读积累笔记和剧情线，在“纠错审核”中处理 agent 发现的问题。

无需等整本书处理完才能阅读。伴读可用的检索能力取决于该书已经生成的摘要、实体和索引。

## 本地运行

后端使用 Python，前端使用 Node.js。基础功能不需要安装本地 AI 模型；使用向量索引和重排时，再安装 AI 依赖并准备模型权重。支持 CUDA GPU，也可以使用 CPU。

从项目根目录配置并安装后端依赖：

```powershell
Copy-Item .env.example backend/.env
python -m pip install -r backend/requirements.txt
```

需要本地嵌入与索引时安装：

```powershell
python -m pip install -r backend/requirements-ai.txt
```

启动后端：

```powershell
cd backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

在另一个终端，从项目根目录启动前端：

```powershell
cd frontend
npm install
npm run dev
```

前端默认运行在 `http://localhost:5173`，通过代理访问 `8000` 后端。模型服务地址、模型名称和密钥可以在设置页配置，支持 OpenAI 兼容接口；接口文档位于 `http://127.0.0.1:8000/docs`。

### 连接 MCP

从项目根目录安装 MCP 依赖：

```powershell
python -m pip install -r backend/requirements-mcp.txt
```

在客户端配置一个 stdio MCP 服务，使用安装了依赖的 Python，并将工作目录设为项目的 `backend` 目录，启动命令为：

```powershell
python -m app.mcp_server --base-url http://127.0.0.1:8000
```

后端需要同时运行。先在阅读器打开一本书，再让客户端调用 `get_reading_context` 获取当前书和安全章。更新工具后，重新连接 MCP 以刷新工具描述和参数。

MCP 通过 HTTP 调用后端，向量库由后端统一管理。

## 数据与模型服务

书稿、阅读进度、笔记、数据库和索引保存在本机的 `data/` 目录，运行数据不进入版本库。密钥加密后保存于本地数据库。

使用远程模型服务时，生成摘要或伴读所需的正文片段、上下文及问题会随请求发送给你配置的服务商；本地嵌入和向量检索在本机执行。

## 技术栈

| 部分         | 实现                                   |
| ------------ | -------------------------------------- |
| 后端         | FastAPI、SQLAlchemy、SQLite、Pydantic  |
| 前端         | Vue 3、Vite、Element Plus              |
| 本地检索     | Qdrant、本地 BGE-M3、可选 BGE reranker |
| 笔记语义缓存 | SQLite，按笔记版本与变化文本增量维护   |
| 伴读接入     | 内置 agent、MCP stdio、配套 Skill      |

## 开发与测试

```powershell
cd backend
python -m pytest tests -q
```

测试默认使用隔离的内存数据库，持久化测试使用专用临时数据库。文件资源位于有限且带进程锁的测试槽位，异常退出后下次回收。

GitHub CI 只安装基础依赖，不安装 torch 或 MCP SDK。AI 业务测试使用替身；未安装 MCP 时，仅跳过需要 SDK 的集成测试，其余后端测试正常运行。安装 `backend/requirements-mcp.txt` 后会自动执行这些 MCP 测试。
