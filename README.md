# 墨读 · RavenRead

本地 TXT 阅读器，提供章节摘要、人物与世界观索引、原文检索，以及能查证和记笔记的 AI 伴读。

## 阅读与书库

- 导入 TXT，预览编码、章节划分，区分正文与番外。
- 目录跳转、阅读进度保存、段落书签，以及日夜模式、字号、字体和阅读宽度设置。
- 书籍信息、正文和整理成果保存在本机。

## 摘要与索引

- 单章或批量生成结构化摘要，支持停止、续跑、失败重试和编辑。
- 按章节维护人物身份、关系、别名与世界观资料，查看变化及来源。
- 正文切块与检索、摘要检索、人物和世界观索引；本地向量能力需安装可选 AI 依赖并准备模型。
- 摘要页统一展示摘要、关键事件、出场人物等字段：没有结构化摘要时使用跟读内容，未提取字段留空；已有摘要可切换查看跟读版本，不覆盖人工编辑。
- 部分跟读显示实际覆盖量。片段概览按顺序展示，不额外调用模型合并；未提取的结构化字段会明确说明，完整跟读计入书籍主页的“已生成”（与结构化摘要按章去重），部分跟读不计入；摘要索引也支持完整跟读内容，同章优先使用结构化摘要，部分跟读不参与建库。

## 自动跟读

在阅读器开启伴读模式，停留在正文章后，后端使用设置中的激活模型处理本章。一次运行固定模型配置，会产生模型调用费用。

1. 分段生成概览和有原文依据的事件，保留已完成片段，支持暂停及重试。
2. 参考本章与前 3 个正文章的事件、相关剧情线，自动整理并保存；不补跑跳过的章节。
3. 无明确关联的事件独立保留。每个片段最多提取 3 条事件，允许零事件，不凑数量。

事件优先记录局面变化、关键行动与结果、新信息，以及明确提出的未解决事项。普通日常动作和重复表态通常只放概览。

跟读同章、同一剧情线合成一个进展节点，保留各条事件及证据；只自动连接不同章节。跨批次只补充本任务创建且未被修改的节点，不自动改名或覆盖人工、agent 的旧节点。单次处理有额度限制，达到额度时可继续，失败显示重试入口。

## 事件与剧情线

剧情线页面采用左右布局：

- **剧情线**：左侧选择名称，右侧查看剧情图或章节列表，展开节点与原文依据。
- **事件**：左侧选择已读正文章，右侧显示事件卡片，包括独立事件，可展开原文及跳转关联剧情线。

剧情线经证据和版本校验后直接保存。前端可编辑标题、概述、阶段、节点结论，移除错挂节点及相关连接；原始事件保留。修改保存为新版本，版本冲突不会覆盖其他窗口的新内容。

节点只引用同章事件和原文，后章新认识另建节点。伴读 agent 和 MCP 仍支持同章多个节点及分支；跟读使用较粗的章节进展粒度。

## 内置伴读与会话记忆

阅读器内可向伴读提问，由它查询笔记、摘要、人物资料及原文，回答问题并保存有依据的发现。跨章梳理需要用户提问或要求整理才会触发。

- 普通模式以当前阅读章为范围，当前章按整章可读处理；笔记和剧情线按可见版本过滤。
- 剧透模式可使用全书正文范围，与普通模式隔离会话上下文；该模式不开放笔记和纠错写入工具。
- 长对话使用近期消息及按需压缩的较早交流，保留原始消息与来源；压缩失败不覆盖已有有效记忆。
- 记忆面板可查看、补充、修正及遗忘读者偏好、约定、猜测和未解决问题。会话记忆与书籍证据笔记分开保存。
- 支持取消对话请求和重复请求识别。

## MCP 与纠错

RavenRead 提供 MCP 工具，外部客户端可主动读取前端阅读进度、检索原文、查询或写入事件与剧情线。MCP 仍受阅读进度限制。

配套 [伴读 Skill](skills/ravenread-companion/) 指导客户端确认进度、查笔记、查原文、保存新发现并回答。WorkBuddy 可导入 [Skill 压缩包](artifacts/ravenread-companion-workbuddy.zip)；实际执行取决于客户端与模型。

摘要、人物、别名和世界观的纠错报告可在“纠错审核”中查看、编辑并确认，随后重建相关实体层或索引；事件与剧情线使用各自的版本修订。纠错不修改小说原文。

## 使用流程

1. 导入 TXT，检查正文与番外划分，打开阅读器。
2. 在设置页配置模型；按需开启自动跟读或向内置伴读提问。
3. 在摘要页查看概览，在剧情线页浏览事件、剧情图并编辑。
4. 按需生成结构化摘要、人物与世界观资料及向量索引。
5. 如使用外部客户端，安装 MCP 依赖并连接服务。

## 本地运行

后端使用 Python，前端使用 Node.js。基础功能不需要安装本地 AI 模型；使用向量索引和重排时，再安装 AI 依赖并准备模型权重。支持 CUDA GPU，也可以使用 CPU。

从项目根目录配置并安装后端依赖：

```powershell
Copy-Item .env.example backend/.env
python -m pip install -r backend/requirements.txt
```

需要本地嵌入与索引时安装：

```powershell
python -m pip install -r backend/requirements-ai.txt
```

启动后端：

```powershell
cd backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

在另一个终端，从项目根目录启动前端：

```powershell
cd frontend
npm install
npm run dev
```

前端默认运行在 `http://localhost:5173`，通过代理访问 `8000` 后端。模型服务地址、模型名称和密钥可以在设置页配置，支持 OpenAI 兼容接口；接口文档位于 `http://127.0.0.1:8000/docs`。

### 连接 MCP

从项目根目录安装 MCP 依赖：

```powershell
python -m pip install -r backend/requirements-mcp.txt
```

在客户端配置一个 stdio MCP 服务，使用安装了依赖的 Python，并将工作目录设为项目的 `backend` 目录，启动命令为：

```powershell
python -m app.mcp_server --base-url http://127.0.0.1:8000
```

后端需要同时运行。先在阅读器打开一本书，再让客户端调用 `get_reading_context` 获取当前书和安全章。更新工具后，重新连接 MCP 以刷新工具描述和参数。

MCP 通过 HTTP 调用后端，向量库由后端统一管理。

## 数据与模型服务

书稿、阅读进度、笔记、数据库和索引保存在本机的 `data/` 目录，运行数据不进入版本库。密钥加密后保存于本地数据库。

使用远程模型服务时，生成摘要或伴读所需的正文片段、上下文及问题会随请求发送给你配置的服务商；本地嵌入和向量检索在本机执行。

## 技术栈

| 部分         | 实现                                   |
| ------------ | -------------------------------------- |
| 后端         | FastAPI、SQLAlchemy、SQLite、Pydantic  |
| 前端         | Vue 3、Vite、Element Plus              |
| 本地检索     | Qdrant、本地 BGE-M3、可选 BGE reranker |
| 笔记语义缓存 | SQLite，按笔记版本与变化文本增量维护   |
| 伴读接入     | 内置 agent、MCP stdio、配套 Skill      |

## 开发与测试

```powershell
cd backend
python -m pytest tests -q
```

测试默认使用隔离的内存数据库，持久化测试使用专用临时数据库。文件资源位于有限且带进程锁的测试槽位，异常退出后下次回收。

GitHub CI 只安装基础依赖，不安装 torch 或 MCP SDK。AI 业务测试使用替身；未安装 MCP 时，仅跳过需要 SDK 的集成测试，其余后端测试正常运行。安装 `backend/requirements-mcp.txt` 后会自动执行这些 MCP 测试。
